# Phase 3: Semantic Analysis Specification & Architecture

This document defines the formal analysis, architectural design, and implementation plan for **Phase 3: Semantic Analysis (Análisis Semántico)** based on the official course requirements (*Compiladores II — Dra. Blanca Guadalupe Estrada Rentería, Universidad Autónoma de Aguascalientes*).

---

## 1. Executive Summary & Goals

The objective of Phase 3 is to design, implement, and integrate the Semantic Analyzer into the existing compiler and IDE. It processes the Abstract Syntax Tree (AST) produced by the syntactic parser to:
1. Apply language semantic rules (syntax-directed translation / attribute grammars).
2. Propagate **inherited attributes** (e.g., `dtype` in declarations) and **synthesized attributes** (e.g., `tipo`, `valor` in expressions).
3. Generate an **Annotated AST** without mutating the original syntax tree (enabling side-by-side comparison).
4. Construct and maintain a genuine **Symbol Table** (supporting insertion, lookup, memory displacement/offset tracking, and scope verification).
5. Perform **type checking**, condition verification, and permissible implicit conversions (e.g., `int` -> `float` promotion).
6. Detect and record semantic errors while applying robust recovery to locate subsequent errors across the source file.
7. Integrate semantic outputs with both the CLI runner (`runner.py`) and the PySide6 IDE GUI (`PanelSim`, `PanelArb`, `PanelErr`, and the semantic view).

## 3. Semantic Analysis Rules & Attributes

### 3.1 Attributes
1. **Inherited Attributes**:
   - `dtype`: Propagated from declaration type (`int`, `float`, `bool`) downward to individual declared variable identifiers (`Var: <id>`).
2. **Synthesized Attributes**:
   - `tipo`: Propagated upward from literal components (`NUMERO_ENTERO` -> `int`, `NUMERO_REAL` -> `float`, `true`/`false` -> `bool`) and symbol lookups (`Id` -> symbol type) through binary and unary operators.
   - `valor`: Constant evaluation when operands are compile-time constants (e.g., `2 + 3 * 4` evaluates to `14`). If non-constant, `valor = None` (never forced).
   - `lineas_ref`: List of line numbers where an identifier is read or written.

### 3.2 Type System & Compatibility Rules
- **Data Types**: `int`, `float`, `bool`, and `error` (for error cascading prevention).
- **Memory Footprint / Displacements**:
  - `int`: 4 bytes.
  - `float`: 4 bytes (standard IEEE single precision / 32-bit).
  - `bool`: 1 byte (aligned or sequential based on project layout).
  - Calculated sequentially starting at displacement `0`.
- **Arithmetic Operators (`+`, `-`, `*`, `/`, `^`)**:
  - `int` op `int` $\rightarrow$ `int`
  - `int` op `float` $\rightarrow$ `float` (implicit promotion of `int` operand)
  - `float` op `int` $\rightarrow$ `float` (implicit promotion of `int` operand)
  - `float` op `float` $\rightarrow$ `float`
  - Any arithmetic operator with `bool` $\rightarrow$ **Error: Invalid operator for operand types**
- **Modulo Operator (`%`)**:
  - `int % int` $\rightarrow$ `int`
  - `float` or `bool` operands $\rightarrow$ **Error: Modulo requires integer operands**
- **Relational Operators (`<`, `<=`, `>`, `>=`, `==`, `!=`)**:
  - `int` vs `int`, `float` vs `float`, `int` vs `float` $\rightarrow$ `bool`
  - `bool` vs `bool` $\rightarrow$ valid only for `==` and `!=` $\rightarrow$ `bool`
  - `bool` with ordering operators (`<`, `<=`, `>`, `>=`) $\rightarrow$ **Error: Invalid relational operator for boolean types**
- **Logical Operators (`&&`, `||`, `!`)**:
  - Operands must evaluate to `bool`.
  - Result is `bool`.
  - If an operand is `int` or `float` $\rightarrow$ **Error: Logical operators require boolean operands**
- **Assignments (`id = expr`, `id++`, `id--`)**:
  - Target variable must exist in the Symbol Table.
  - Type matching:
    - `id` of type `int` assigned `int` $\rightarrow$ OK.
    - `id` of type `float` assigned `float` or `int` $\rightarrow$ OK (with conversion if `int`).
    - `id` of type `int` assigned `float` $\rightarrow$ **Error: Type mismatch (cannot assign float to int without explicit cast)**.
    - `id` of type `bool` assigned non-`bool` or vice versa $\rightarrow$ **Error: Type mismatch in assignment**.
    - `id++` / `id--` requires variable of type `int` (or numeric).
- **Control Structures (`if`, `while`, `do-while`)**:
  - Condition expressions must evaluate to `bool`.
  - If condition is non-boolean $\rightarrow$ **Error: Condition expression must be boolean**.
- **I/O Statements (`cin`, `cout`)**:
  - `cin >> id`: `id` must be declared in the Symbol Table.
  - `cout << expr`: `expr` can be `cadena`, `int`, `float`, or `bool`.

## 4. Minimum Required Semantic Errors (Official Syllabus)

| # | Error Code / Description | Detection Scenario |
|---|--------------------------|---------------------|
| 1 | **Uso de variable no declarada** | An identifier used in an expression, assignment, or `cin` does not exist in the Symbol Table. |
| 2 | **Declaración duplicada** | An identifier is declared more than once within the same scope (`main`). |
| 3 | **Incompatibilidad de tipos** | Operands in an expression cannot be combined (e.g., `int` + `bool`). |
| 4 | **Conversión de tipos no válida** | Attempting an illegal coercion (e.g., assigning `float` to `int` or implicit bool-to-numeric casting). |
| 5 | **Uso indebido de operadores** | Operator not applicable to operand types (e.g., `!` on an integer, or `%` with floats). |
| 6 | **Inconsistencia de tipos en asignaciones** | Expression type does not match the target variable's type. |
| 7 | **Tipo no booleano en condición** | The guard expression in `if`, `while`, or `do ... while` is not of type `bool`. |

## 5. Architectural Components to Implement

### 5.1 New Module: `ide/compilador/semantico.py`
- `EntradaSimbolo`: Data structure holding symbol info (`nombre`, `tipo`, `linea_decl`, `lineas_uso`, `desplazamiento`, `ambito`).
- `TablaSimbolos`: Scope-aware dictionary storing `EntradaSimbolo` objects, offering `insertar()`, `buscar()`, `contiene()`, `obtener_todas()`.
- `NodoAnotado`: Clone of `NodoArb` extended with attributes:
  - `tipo_dato: str` (e.g., `"int"`, `"float"`, `"bool"`, `""`)
  - `valor_cte: Any` (pre-computed constant value when statically known)
  - `conversion: str` (e.g., `"int -> float"` if an operand had implicit promotion)
  - `etiqueta_anotada`: String representation displaying attributes (e.g., `Num: 23 [tipo: int, val: 23]`, `Op: + [tipo: float]`).
- `AnalizadorSemantico`: AST visitor traversing declarations, statements, expressions, and conditionals:
  - Phase 1: Declarations registration into `TablaSimbolos` with memory offset calculation.
  - Phase 2: AST traversal, attribute assignment/synthesis, type checking, constant folding, and error gathering.
- `analizar_semantica(arbol: NodoArb) -> Tuple[NodoAnotado, TablaSimbolos, List[ErrorSemantico]]`.

### 5.2 Enhancements to Data Models (`ide/modelos/datos.py`)
- Update or extend `Sim` to include memory offset and reference lines for UI presentation (`nombre`, `tipo`, `ambito`, `linea`, `desplazamiento`, `referencias`).
- Ensure `ResultadoCompilacion` carries annotated tree and semantic symbols.

### 5.3 CLI Integration (`runner.py`)
- Run lexical $\rightarrow$ syntactic $\rightarrow$ semantic pipeline.
- If lexical or fatal syntactic errors occur, halt before semantic analysis with clear feedback.
- Produce output files in `outputs/`:
  - `tabla_simbolos.json` & `tabla_simbolos.txt`
  - `ast_anotado.txt`
  - `errores_semanticos.json` & `errores_semanticos.txt`

### 5.4 IDE UI Integration (`ide/ventana.py`, `ide/servicios/compilador.py`, `ide/ui/`)
- In `ServicioCompilador`: execute semantic analyzer when `fase == "semantic"` or in full compilation.
- In `PanelSim`: update table columns to include `[Nombre, Tipo, Desplazamiento, Línea Decl., Referencias]`.
- In `_tabs_der` ("Análisis"):
  - Keep "Árbol Sintáctico" (`PanelArb` displaying original AST).
  - Replace the static placeholder "Semántico" with an interactive annotated tree viewer (`PanelArb` displaying `NodoAnotado`), allowing immediate comparison.
- In `_tabs_abj`: display semantic errors in `PanelErr` with line navigation and editor highlights.
